# geo-atlas 要件定義

## 1. コンセプト

「地形から"なぜ"を読み解く地球儀」。
Googleアースのように地球儀を回して拡大・タップすると、その土地を次の4層で解説する。
地理を起点に、歴史と文化を因果関係で結びつけて学べるようにする。

| 層 | 内容 |
|---|---|
| ① 地形・自然 | 標高、河川、気候、プレート、地質 |
| ② 人の営み | 都市の立地理由、農業、交易路、交通 |
| ③ 歴史 | 地形がどう歴史に影響したか |
| ④ 文化 | 食、建築、宗教、言語、祭り（地形・歴史との関係で説明する） |

## 2. 利用前提

- 利用者は1人（個人利用）。ログイン機能は不要
- 主な端末はiPhoneのSafari。ホーム画面に追加して、アプリのように使う
- 主な利用シーンは旅先。片手操作、屋外での見やすさ、通信不安定への対策が必要

## 3. 費用ルール（最重要・厳守）

**運用費0円、かつ従量課金が発生し得る構成を一切使わないこと。**

- 禁止事項
  - Claude API、OpenAI APIなど、生成AIのAPIを実行時に呼び出すこと
  - APIキーの登録やクレジットカードの登録が必要なサービス（無料枠ありでも不可）
  - 自前のサーバーやデータベース（Supabase、Firebaseなども使わない）
- 使用してよいもの（すべてキー不要・登録不要）
  - 地図：OpenFreeMap（`https://tiles.openfreemap.org/styles/liberty` など）
  - 標高データ：AWS Terrain Tiles（Terrarium形式）、またはMapLibre公式サンプルで使われているキー不要のDEM
  - 解説の補助情報：Wikipedia REST API / MediaWiki Action API（日本語版優先、英語版フォールバック）
  - ホスティング：GitHub Pages（GitHub Actionsでデプロイ）
- 新しい外部サービスを追加したくなった場合は、実装前に必ず「キー不要か」「課金登録不要か」を確認して報告すること
- 各データの利用規約に従い、クレジット表記（© OpenStreetMap contributors など）を画面に表示すること

## 4. 解説データの作り方（API課金ゼロの仕組み）

解説文は、アプリ実行時にAIで生成しない。
**開発時にClaude Codeが作成し、JSONファイルとしてリポジトリに保存する。** アプリは保存済みのJSONを読むだけにする。

- 保存場所：`public/data/places/{id}.json`
- 一覧：`public/data/places/index.json`（id、名前、緯度経度、規模のみ。地図上のマーカー表示用）
- 地点の追加運用：利用者がClaude Codeに「〇〇の解説データを追加して」と依頼する。Claude CodeがJSONを作成してコミットし、自動デプロイされる。この手順を `CLAUDE.md` に明記すること
- 旅行パック：`public/data/trips/{trip-id}.json` に、旅行ごとの地点IDリストを置く。例：「北海道旅行」→ 札幌・小樽・富良野・洞爺湖

### 地点データの形式（例）

```json
{
  "id": "kyoto",
  "name": "京都",
  "name_local": "Kyoto",
  "lat": 35.0116,
  "lng": 135.7681,
  "scale": "city",
  "summary": "三方を山に囲まれた盆地に築かれた、千年の都",
  "layers": {
    "terrain": "解説文…",
    "life": "解説文…",
    "history": "解説文…",
    "culture": "解説文…"
  },
  "why_chain": ["盆地で守りやすい", "川と水運に恵まれる", "都が置かれる", "寺社と工芸が集積"],
  "look_for": ["旅先で実際に見て確認できる地形ポイント（例：東山から見る盆地の形）"],
  "related": ["nara", "lake-biwa"],
  "sources": [{ "title": "Wikipedia: 京都市", "url": "https://ja.wikipedia.org/wiki/京都市" }],
  "note": "Claude Codeが一般的知識とWikipediaを元に整理。要確認箇所があれば記載"
}
```

- `scale` は `country` / `region` / `city` / `spot` の4段階
- 解説は事実と解釈を区別する。地形と歴史の因果関係のうち、通説ではなく解釈にあたるものは「〜と考えられる」と書く
- 1つの層は200〜400字程度。スマホで読みやすい長さにする

## 5. 機能要件（MVP）

### 5-1. 地球儀・地図

- ライブラリはMapLibre GL JS（最新安定版）を使う。globeプロジェクションで地球儀を表示する
- 回転・ピンチズーム・傾きの操作に対応する。拡大すると自然に平面地図へ移行する
- 地形の陰影（hillshade）を常時表示する。3D地形はボタンでオン・オフを切り替える
- 地名ラベルは日本語優先（`name:ja`）、なければ現地名で表示する
- 内蔵解説データがある地点にマーカーを表示する

### 5-2. 現在地

- 「現在地」ボタンで現在位置へ移動し、位置を表示する
- 位置情報の許可が得られない場合も、アプリは通常どおり使えるようにする

### 5-3. タップで解説（ボトムシート）

- 地図をタップすると、画面下から解説シートが出る
  - 半分表示 → 全画面表示 → 閉じる、の3段階
- 表示の優先順位
  1. タップ地点の近くに内蔵データがある → 4層解説をタブで表示（地形／営み／歴史／文化）
  2. ない場合 → Wikipediaのジオサーチで周辺記事を最大5件表示し、選ぶと要約を表示する
  3. どちらもない場合 → 緯度経度、標高（DEMから取得）、地図上の地名を表示する
- 解説の下に「関連地点」「出典リンク」「旅先で見るポイント」を表示する
- 一度表示したWikipediaの要約は端末に保存し、オフラインでも再表示できるようにする

### 5-4. 旅行パック（オフライン準備）

- 画面上で旅行パックを選び「事前ダウンロード」を押すと、該当地点の解説JSONをキャッシュする
- 旅先でオフラインでも、解説一覧と各解説を読めるようにする
- 地図タイルは「閲覧済みの範囲がキャッシュに残れば表示される」程度でよい。全面的なオフライン地図はMVPの対象外

### 5-5. 学習記録

- 解説を開いた地点を「訪問済み」として端末内（localStorage / IndexedDB）に記録する
- 記録した地点を地図上で色分け表示し、一覧でも確認できるようにする

## 6. 非機能要件

- iPhone Safariでの快適な動作を最優先にする。初回表示3秒以内を目安とする
- PWAにする（manifest、アイコン、Service Worker）。ホーム画面から全画面で起動できること
- 片手操作を前提に、主要ボタンは画面下部に配置する。タップ領域は44px以上とする
- 屋外で見やすい高コントラスト配色にする。ダークモードにも対応する
- バッテリー配慮のため、不要なアニメーションや常時GPS追跡はしない

## 7. 技術構成

- Vite + TypeScript（フレームワークは原則なし。必要ならPreactまで）
- maplibre-gl、vite-plugin-pwa（Workbox）
- GitHub Actionsで、mainブランチへのpush時にGitHub Pagesへ自動デプロイする
- ディレクトリ例：`src/`（地図・UI・データ読込）、`public/data/`（解説JSON）、`docs/`（要件定義）

## 8. 開発フェーズ

各フェーズの終わりに、iPhoneで確認する手順（公開URLで何を見ればよいか）を報告すること。

1. **土台**：Vite + TS + MapLibreの地球儀、地形陰影、日本語地名、現在地ボタン、GitHub Pagesへの自動デプロイ
2. **タップ解説**：ボトムシート、Wikipediaジオサーチ・要約、標高表示
3. **内蔵解説データ**：データ形式の実装、初期30地点の作成（日本15・世界15。地形と歴史の因果が分かりやすい場所を選ぶ）、地点追加手順を `CLAUDE.md` に記載
4. **PWA・オフライン**：Service Worker、旅行パックの事前ダウンロード
5. **学習記録**：訪問済み地点の記録・表示
